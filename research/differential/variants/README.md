# Concrete experimental hashes

Generated by `../build_variants.py` from the frozen pre-v4 reference source.
`manifest.json` records exact source fingerprints and definitions. These
files preserve the comparison experiments. A's algorithm was subsequently
promoted to `src/rainstorm.cpp` as v4.0.0; the other candidates remain experiments.

| Name | Right-round change | Finalization | Domain block |
| --- | --- | --- | --- |
| A | Final subtraction goes to low word 0 | Original | None |
| B | Final counter subtraction is doubled | Original | None |
| C | Same as A | Four alternating right/left rounds | `RNSTEXP1`, version, size, seed, length, three zero words |
| D (optional) | None | Four alternating right/left rounds | None |

C and D use four final rounds for every digest size. In particular, the
256-bit comparison keeps the original number of final rounds; it changes
their direction. C additionally absorbs one explicit 64-byte domain block.
For 64/128/512-bit outputs, this experimental fixed schedule also changes the
number of final rounds. Those are different comparisons and should not be
confused with the 256-bit result.

Validation steps, executed before candidate acceptance:

```
python3 research/differential/test_variants.py
c++ -std=c++17 -O1 -fsanitize=address,undefined \
  research/differential/variants/sanitizer_test.cpp -o /tmp/rain-variant-sanitizer
/tmp/rain-variant-sanitizer
python3 research/differential/scan_variants.py
python3 research/differential/prepare_variant_smhasher3.py
```

`test_variants.py` compares the native full hashes with a separate Python
model using the verified round model for the right branch and the original
native left branch. It also tests streaming across varied chunk and block
boundaries. `checks.json` holds the results and generated vectors once that
check completes. The sanitizer executable runs larger streaming cases.
The bounded differential screens produce `differential-{a,b,c,d}.json`.
Each screen uses alpha 0.0025 so their confidence families jointly have error
at most 0.01, under the stated IID model. This joint statement covers these
four screens, not additional unrelated campaigns or SMHasher3's tests.

All SMHasher3 candidate registrations have the same test-budget metadata as
the exact-source original. Upstream's Testlib is unmodified. The separate
BLAKE3 control retains upstream's implementation and seed adaptation, but
its control registration removes VERY_SLOW so it receives matched test
budgets. Original upstream registrations remain available.

Passing these checks does not prove cryptographic security. Invertibility of
A/B's round does not imply invertibility of the complete digest function.
